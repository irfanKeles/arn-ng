Installation

Not on npm yet.&ngsp;@arn-ng/ui has not been published. These steps are for its first release, 0.1.0; they have been run against a local registry.

Add the package, its theme and, if you want, its configuration.

The library supports these versions of its peer dependencies:

    @for (peer of peers; track peer.name) {
  • {{ peer.name }}&ngsp;{{ peer.range }}
    • }

It is built on Angular CDK, which is why the CDK is a peer dependency. A newer Angular major is added to these ranges once it has been tested.

npm installs @angular/cdk with it, as a peer dependency, in the version that matches your Angular. Other package managers have not been tried yet.

Import the theme once, in the application's global stylesheet. It defines the design tokens (colors, sizes, density), the light and dark color schemes and the few classes the library needs; it styles none of your elements.

Without a class the theme follows the system's light or dark preference; .dark or .light on an element forces one.

provideArn() in the root providers sets the application-wide configuration. Every field is optional, and without provideArn() every setting keeps its default. With applyToDocument: true the color scheme, direction and density are also written to the <html> element, so the whole page follows them.

English texts are built in. Other languages are separate imports; Turkish is the first one:

Every field, sections and runtime changes: Configuration.

Everything is imported from a secondary entry point, so an application only pays for what it uses. @arn-ng/ui itself exports nothing, and paths inside the package are not part of its API: they do not resolve.

  • @arn-ng/ui/core: configuration and the shared overlay service
  • @arn-ng/ui/ripple: the ripple directive
  • @arn-ng/ui/locales/tr: Turkish texts
  • @arn-ng/ui/theme.css: the theme (a stylesheet, not a script)
