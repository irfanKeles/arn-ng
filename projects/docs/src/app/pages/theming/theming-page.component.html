Theming

Colors, sizes and density are CSS custom properties in one file, @arn-ng/ui/theme.css. Change a token and every component that uses it follows.

Import the theme once, after which every token is available on :root. It defines tokens, the color schemes and the few classes the library needs; it paints none of your elements, the page included. The values follow shadcn/ui's neutral theme.

Tokens come in layers. The palette holds raw values; semantic tokens such as --arn-primary point to the palette and are what components use. A component computes its own tokens, such as its height, on its own element from the semantic ones. The shared scales:

--arn-radius-sm and --arn-text-sm are steps of a scale, not the sm size of a component.

The semantic colors have shadcn/ui's names with the --arn- prefix (--arn-primary is shadcn's --primary). Each one has a light and a dark value in a single light-dark().

Without a class the theme follows the system's preference. .dark or .light on an element forces a scheme for everything inside it, and they nest. The colorScheme setting writes these classes for you, on <html> with applyToDocument or on a section with arnConfig (see Configuration).

Components come in five sizes, xs to xl, md by default. One set of control tokens gives each size its height, inline padding, font size, icon size and gap, so a button, an input and a select of the same size line up. A component applies them to its own element:

The boxes below are sized exactly that way and show the height the browser gives them. No height drops below --arn-control-min-size, 24px, the WCAG 2.2 minimum target size.

Density makes controls shorter and narrower without making their text smaller. data-density="compact" on an element sets --arn-density to 0.875 for everything inside it; the factor applies to height and inline padding only, and the 24px floor still holds, so xs keeps its height. The density setting writes the attribute, like the color scheme.

Set a token after the theme import to change it everywhere, or on a class to change it for one part of the page. No !important is needed: the same specificity and a later rule are enough.

Derived tokens do not follow a base changed in a part of the page. A var() is resolved where the token is defined, on :root, so changing --arn-radius on .brand leaves --arn-radius-md as it was.
