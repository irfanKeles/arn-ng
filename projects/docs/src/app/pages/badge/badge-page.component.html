Badge

<arn-badge> is a small label, a count or a dot. Put arnBadge on an <a> and the badge is a link.

The styles come with the component; the tokens they read are part of the theme file, which the application adds once. The badge has one size: it is not a control, so the size and density settings do not change it.

Four variants, with the shadcn/ui names. Without variant the badge is default. Use destructive for an error or a state that needs attention, secondary and outline for quieter labels.

With count the badge shows the number instead of its content. A count of 0 hides the badge; showZero shows it. Above max (99 by default) it shows as max followed by "+". A single digit is a circle.

dot draws a small circle without text. It has no visible text, so give it a label: the badge writes it as visually hidden text, for assistive technology. A dot only says that something is there; when the reader needs to know what, say it in text.

A dot is a graphic, so it needs 3:1 against the background (WCAG 1.4.11): the secondary and outline dots use --arn-muted-foreground, because --arn-secondary and --arn-border are too faint for that.

There is no icon input: put an <svg> before the text, after it or on both sides. It takes 12px, and the gap keeps it 4px from the text. Hide it from assistive technology with aria-hidden="true" when the text says the same.

The badge does not mirror icons in right-to-left pages: a directional icon, like the arrow here, needs the arn-rtl-mirror class of the theme.

loading shows a spinner at the start, in place of the start icon; the text stays and the badge gets aria-busy="true". With reduced motion the spinner keeps turning, three times slower. The spinner is part of the badge; there is no end position.

The start icon is the <svg> right after the spinner. A badge with only an end icon loses that icon while loading.

On an <a> the badge is a real link: href, routerLink and opening in a new tab work as they always do. Only a link badge has a hover fill and a focus ring; <arn-badge> is not interactive. Do not put a link badge inside a button.

A link has no native disabled state, so disabled on an <a arnBadge> sets aria-disabled="true", takes the link out of the tab order and cancels its clicks (routerLink included). The link keeps its href. On <arn-badge> it has no effect.

Inside the label of a button a badge is plain content. With the arnButtonBadge attribute it sits on the button's top inline-end corner and is hidden from assistive technology: put the count in the button's name, as the second example does. A count of 0 hides it there too.

  • No role.&ngsp;<arn-badge> is text in reading order; a link badge is a link.
  • Changes are not announced. The badge has no live region: it does not know what its number means. When a change matters, announce a sentence yourself with the CDK LiveAnnouncer.
  • On a button. A corner badge has aria-hidden="true"; the button's name carries the count. A dot there needs no label of its own.
  • Focus ring. A link badge shows a 3px ring in --arn-ring (--arn-destructive for destructive) for keyboard focus, and its border takes the ring color. In forced-colors mode an outline in the system color takes its place.
  • Contrast. Text against fill is at least 4.5:1 in every variant, and on a link under the pointer, in light and dark. A dot has at least 3:1 against the background. A disabled link is exempt, as every inactive control is.

The rules every component must meet: Accessibility.

The component has no outputs and no public methods.

The badge defines none of these tokens: it reads each with the library value as the fallback. Set one on a container and every badge inside follows; set it on one badge and only that one changes.

The library's rules have no specificity of their own, so a single class of yours wins over them.
