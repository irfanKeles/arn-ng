Configuration

One set of settings, ArnConfig, for the whole application, a part of the page or a single component.

Each setting is decided by the first of these levels that gives it a value:

  1. The component's own input, for example size="sm".
  2. The nearest arnConfig section around it.
  3. The application: provideArn(), changed at runtime through ArnConfigService.
  4. The library default.

undefined on any level means "not given": the next level decides. Two defaults come from the environment: locale from Angular's LOCALE_ID, and direction from the nearest direction in effect. Colors, fonts and borders are not settings; they are CSS tokens (Theming).

Call provideArn() once in the root providers (Installation shows where). Every field is optional.

Density, color scheme and direction work through CSS. Their values only change the page once they are written to an element: applyToDocument: true writes them to <html> and keeps them up to date. Without it, provideArn({ density: 'compact' }) changes the setting but not what you see. size needs nothing: a component applies it to itself. The library never writes <html lang>; the language of the content is the application's to set.

The arnConfig directive takes the same eight fields as inputs and applies them to everything inside it. Sections can be nested; an inner one overrides only what it gives. It writes data-density, .dark or .light and an explicit dir to its own element, so its part of the page changes at once.

The service changes the application level while the application runs. Each field is also a signal that holds the current value. The switches in this site's header use it.

injectArnConfig() reads the configuration in effect where a component is placed, with every level applied. With a key and the component's own input it applies the first level too: the input wins when it is given. A component should read settings only this way, so the precedence stays the same everywhere.

Two fields decide the language of the library. locale sets day and month names, which come from the browser's Intl. messages sets every other text; English is built in, and a partial object changes only what it names. Turkish ships as @arn-ng/ui/locales/tr. A locale does not bring its texts: give both.

The component below reads both through injectArnConfig(). Switch Language in the header to Turkish: it changes at once.

The same component in three places. The second section gives only a locale: the names turn German, the texts stay those of the application. The third gives a locale and the Turkish texts, so it stays Turkish whatever the header says.

The library's styles use logical properties, so they follow the direction of the place they are in. For a whole application, set dir on <html>; it is also right when the page is rendered on the server. A section with direction changes one part of the page, and the CDK parts of the library follow it too.

Like density, provideArn({ direction: 'rtl' }) alone changes only the setting, not the page: add applyToDocument: true, or set dir yourself. An icon that points in a direction, such as an arrow, gets the arn-rtl-mirror class and is mirrored in RTL; one that does not, such as a check mark, keeps its shape. The ripple starts from the pointer in both directions.
